Sieve documentation

Everything you need to run Sieve, point an app at it, and tune it for your traffic. Sieve speaks the OpenAI API, so most apps only change their base URL.

Quickstart

Sieve needs no API key to start. Two mock models answer until you add a real provider, so you can try caching and fallback for free.

Option 1: download a release

Get the file for your computer from the latest release, extract it, and run start-sieve.bat on Windows or ./start-sieve.sh on macOS and Linux. Then open http://localhost:8080.

Option 2: Docker

docker run -p 8080:8080 ghcr.io/prm01/sieve:latest

For the full stack with Redis, Prometheus and Grafana: docker compose up --build in a clone of the repository.

Option 3: from source

git clone https://github.com/Prm01/sieve && cd sieve
go run ./cmd/sieve        # needs Go 1.22 or newer

Try it

curl -i localhost:8080/v1/chat/completions \
  -d '{"messages":[{"role":"user","content":"How do I reset my password?"}]}'
# X-Sieve-Cache: MISS

curl -i localhost:8080/v1/chat/completions \
  -d '{"messages":[{"role":"user","content":"Password bhool gaya, kya karu"}]}'
# X-Sieve-Cache: HIT    X-Sieve-Similarity: 1.0000
On Windows PowerShell, curl is not the real curl. Use curl.exe, or the console in your browser.

How a request flows

  1. Authenticate. The API key maps to a tenant. With no keys configured, the client IP is used and the gateway is open.
  2. Rate limit. One token from the tenant's bucket. An empty bucket returns 429 with Retry-After.
  3. Decide whether to cache. Only single-turn requests are cached. Prompts that match a privacy pattern, or that send X-Sieve-Cache: off, bypass it.
  4. Embed and search. The prompt becomes a 512-dimension unit vector and is compared with every live entry in its partition: the same tenant, model and system prompt.
  5. Hit. At or above the threshold, the stored answer is returned, streamed or not.
  6. In flight. If a similar prompt is being answered right now, wait for that answer instead of calling a model again.
  7. Miss. The router tries providers in order. Retryable failures fall through to the next one, and three in a row open that provider's circuit breaker for 30 seconds.
  8. Store. The answer is cached, even if the client disconnected, and synced to every replica through Redis.

Config file

For more control, put settings in a JSON file and point SIEVE_CONFIG at it. Durations accept "30s", "168h" or a number of seconds.

{
  "threshold": 0.85,
  "ttl": "168h",
  "rate_limit": { "capacity": 20, "refill_per_sec": 1 },
  "router": { "timeout": "60s", "failure_threshold": 3, "cooldown": "30s" },
  "providers": [
    { "name": "claude", "type": "anthropic", "model": "claude-haiku-5-5", "api_key_env": "ANTHROPIC_API_KEY" },
    { "name": "openai", "type": "openai", "base_url": "https://api.openai.com/v1", "model": "gpt-4o-mini", "api_key_env": "OPENAI_API_KEY" },
    { "name": "local-llama", "type": "openai", "base_url": "http://localhost:11434/v1", "model": "llama3.2" }
  ],
  "api_keys": { "sk-sieve-team-a": "team-a" },
  "admin_key": "change-me",
  "synonyms": { "bhool": "reset", "forgot": "reset", "kya": "", "hai": "" }
}

A complete example is in examples/config.example.json. Use api_key_env rather than api_key so secrets stay out of the file.

Providers

typeWorks withNeeds
anthropicClaude models through the Messages API, streamedmodel, API key
openaiOpenAI, Azure OpenAI, Groq, Together, OpenRouter, Ollama, vLLM, LM Studiobase_url, model, key if the server needs one

Providers are tried in the order listed. Timeouts, 408, 409, 429 and 5xx responses fall through to the next one. 400 and 401 do not, because they would fail on every provider.

Embedders

The hash embedder is built in and needs no API. It matches words, spelling variants (character trigrams) and the synonyms you list, which suits FAQ-style traffic. It does not understand meaning the way a neural model does.

For open-ended traffic, use an embeddings API:

SIEVE_EMBEDDER=openai
SIEVE_EMBED_BASE_URL=http://localhost:11434/v1   # or https://api.openai.com/v1
SIEVE_EMBED_MODEL=nomic-embed-text               # or text-embedding-3-small
Re-tune the threshold after switching embedders. Scores from different embedders are not comparable, so 0.85 may be too strict or too loose.

Tuning the threshold

The threshold trades hit rate against wrong answers. On the benchmark workload:

ThresholdFrom cacheWrong answers
0.5085.4%12.8%
0.7079.8%2.9%
0.8074.1%0.1%
0.85 (default)70.5%0.0%
0.9065.0%0.0%
  1. Run with the default for a day and open the Nearest-match similarity panel in Grafana (sieve_cache_similarity).
  2. Spot-check misses that scored just under the threshold. If they are true paraphrases, lower it by 0.02 to 0.05.
  3. Run make sweep on a sample of your own prompts to see the trade-off before changing production.

Chat completions

POST/v1/chat/completions. Same shape as OpenAI. content can be a string or an array of text parts.

{
  "model": "sieve",
  "stream": false,
  "max_tokens": 512,
  "messages": [
    { "role": "system", "content": "You are a helpful support agent." },
    { "role": "user", "content": "What is your refund policy?" }
  ]
}

The response is a standard chat completion with one extra field, sieve:

{
  "id": "chatcmpl-1f3c...",
  "object": "chat.completion",
  "choices": [{ "index": 0, "message": { "role": "assistant", "content": "Refunds are issued..." }, "finish_reason": "stop" }],
  "usage": { "prompt_tokens": 7, "completion_tokens": 22, "total_tokens": 29 },
  "sieve": { "cache": "hit", "similarity": 0.97, "entry_id": "358f4983e8cc...", "matched_prompt": "what is your refund policy", "provider": "claude" }
}

Streaming

With "stream": true, the response is server-sent events in the OpenAI chunk format, ending with data: [DONE]. The last chunk before it carries the sieve object. Cache hits stream too, as one chunk.

Errors

StatusMeaning
400Body is not valid JSON, messages are empty, a role is unknown, or the prompt is over the length limit.
401API keys are configured and the request sent none, or an unknown one.
429The tenant's bucket is empty. Wait for Retry-After seconds.
502Every provider failed. The body lists each attempt and its error.
503No provider is available: all disabled or their breakers are open.

Response headers

HeaderMeaning
X-Sieve-CacheHIT, MISS or BYPASS.
X-Sieve-Coalescedtrue when the answer came from a concurrent request's model call.
X-Sieve-SimilarityScore of the nearest cached prompt, from 0 to 1.
X-Sieve-EntryThe cache entry served or created. Use it for feedback.
X-Sieve-ProviderThe provider that answered.
X-Sieve-Latency-MsTime spent inside the gateway.
X-RateLimit-RemainingTokens left in the bucket.

Send the request header X-Sieve-Cache: off to skip the cache for one request.

Feedback

POST/v1/feedback stops a cached answer from being served. Use the id from X-Sieve-Entry.

curl localhost:8080/v1/feedback -d '{"entry_id": "358f4983e8cc...", "helpful": false}'

Admin endpoints

When SIEVE_ADMIN_KEY is set, these need Authorization: Bearer <admin key>.

EndpointDoes
GET/v1/cache/statsEntry counts, top entries by hits, hit rate.
GET/v1/cache/entries/{id}One entry, without its vector.
DELETE/v1/cache/entries/{id}Remove one entry everywhere.
GET/v1/providersEach provider's breaker state: healthy, open or disabled.
POST/v1/providers/{name}/disableTake a provider out of rotation. /enable brings it back.

Public endpoints: GET /healthz, GET /v1/models, and GET /v1/public/stats, which returns aggregate numbers only, never prompts, answers or tenant names.

Deploying

  • Render: the Deploy to Render button creates the gateway and a Redis-compatible store from render.yaml.
  • Fly.io: fly launch --copy-config && fly deploy uses fly.toml.
  • Kubernetes: deploy/k8s/sieve.yaml runs three replicas with an autoscaler, health probes and a read-only root filesystem.
  • Any container platform: set SIEVE_REDIS_URL and at least one provider key.

Security checklist

  • Set SIEVE_API_KEYS on any gateway reachable from the internet. Without it, anyone can use your provider keys.
  • Set SIEVE_ADMIN_KEY so nobody else can read or delete cache entries or disable providers.
  • Keep Redis on a private network with a password. It holds prompts and answers.
  • Set a low rate limit and a spending cap with your provider on a public demo.
  • Review the privacy patterns for your domain and add your own through privacy_patterns.

Troubleshooting

SymptomFix
Everything is a MISSCheck the similarity header. Scores just under the threshold mean it is too strict, or the embedder needs synonyms for your wording.
Everything is a BYPASSThe prompt matched a privacy pattern, the request had several turns, or X-Sieve-Cache: off was sent.
Answers say "Mock answer to..."No provider key was found, so the mock models are answering. Set ANTHROPIC_API_KEY or another key and restart.
connect to redis on startRedis is not reachable at SIEVE_REDIS_URL. Remove the variable to run with an in-memory cache.
address already in useAnother Sieve or app is on port 8080. Stop it or set SIEVE_ADDR=:8081.
503 no_provider_availableEvery provider is disabled or its breaker is open. Check /v1/providers; breakers close after 30 seconds.

Limitations

  • The hash embedder is lexical. Use an embeddings API for open-ended traffic.
  • Vector search is exact, which stays fast up to roughly 10,000 entries per partition.
  • Request coalescing works within one replica.
  • Privacy detection is pattern-based. It errs towards bypassing but is not a data-protection review.
  • The Redis client has no TLS or cluster mode yet.
